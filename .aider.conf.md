# Aider Base Instructions

Thse rules apply to every Aider session in this repository. Follow them consistently and without deviation.

---

## Logging Rules

### Changelog
- After completing any set of edits, append a summary of the changes to `CHANGELOG.md`.
- All changelog entries must be added **inside** the `[Unreleased]` section, between the delimiters:
`<!-- ENTRY-START -->`
`<!-- ENTRY-END -->`
- Never modify or reorder existing changelog entries.
- Keep changelog bullet points concise and factual.

### Prompt Log
- For every user prompt, append the exact prompt test to `PROMPTLOG.md`.
- Each new prompt entry must be appended **after** the delimeter:
`<!-- PROMPT-ENTRY-END -->`
- Each prompt entry must include:
  - A sequential entry number
  - The date
  - The full prompt text
  - A short summary of actions taken
- Never modify or rewrite previous prompt log entries.

## Documentation Rules

### C# XML Documentation
- Always add XML documentation comments in all applicable and supported C# areas.
- XML comments must be concise: **1-3 sentences**.
- Use XML comments for:
  - Classes
  - Interfaces
  - Methods
  - Public properties
  - Public fields (if applicable)

### Traditional C# Comments
- When XML comments are not supported (e.g., `Program.cs` top-level statements), use tratidiontal `//` comments.
- Keep these comments concise: **1-3 sentences**.

### Razor View Documentation
- Use Razor comment blocks (`@* *@`) for all Razor documentation.
- Every Razor view must include a **top-of-file Razor comment block** summarizing the entire view in **1-5 sentences**.
- If the Razor file contains an `@code` block:
  - Add an additional Razor comment **immediately before** the `@code` block.
  - This comment must follow the same concise style as XML/traditional comments (1-3 sentences).

### General Documentation Behavior
- Comments must be clear, direct, and free of filler language.
- Do not restate obvious code behavior; focus on intent, purpose, and constraints.
- Maintain constistent formatting and indentation.

---

## Behavioral Rules

- Follow all delimiter rules exactly as defined.
- Never modify or delete existing content in `CHANGELOG.md` or `PROMPTLOG.md`
- Only append new entries in the designated zones.
- Maintain consistend formatting across sessions.
- When making code changes, prefer clarity, maintainability, and architectural consistency.
- Do not introduce stylistic drift across sessions.
